# مرحله ۸ — تحویل

> هدف: بسته‌ی نهایی به ترتیب ثابت + بلوک‌های تحویل به اسکیل‌های بعدی.
> در خروجی هیچ نام مرحله، «Stage» یا «LU#» دیده نمی‌شود — مگر در لاگ لوپ و بخش فرض‌ها.

## ۸.۲ — بلوک‌های تحویل

### الف) بریف تصاویر مرجع ← `gpt-image-2-prompt-generation` (فقط animation / hybrid)
Omni Flash با تصویر مرجع بسیار قابل‌کنترل‌تر است. برای یکدستی شخصیت‌ها بین قسمت‌ها، اول تصاویر مرجع ساخته شوند:
```
REFERENCE IMAGE BRIEF — [عنوان سریال]
Style lock: [از قفل آرت]
Palette: [...]
1. Character sheet — [قهرمان]: front / 3/4 / side, neutral pose, [لباس، آیتم شاخص]
2. Character sheet — [راهنما]: ...
3. Environment — [ایستگاه ۱]: [امضای بصری] ...
4. Environment — [ایستگاه ۲] ...
5. Key prop — [شیء شاهد اصلی] ...
Rules: no third-party logos, no random text, 9:16 framing for environments
```

### ب) بلوک ورودی ← `omni-flash-motion-prompt` (هر قسمت یک بلوک کامل)
برای هر قسمت یک بلوک کامل با استوریبورد همه‌ی کلیپ‌ها نوشته می‌شود. «به همین ترتیب» یا ارجاع به قسمت قبل ممنوع است.
این بلوک جواب‌های مرحله ۱ و استوریبورد مرحله ۳ آن اسکیل را از پیش پر می‌کند:
```
OMNI HANDOFF — [عنوان سریال] · Episode [n]/[N]
Flow: classicMD
Reference images: [فهرست تصاویر مرجع بخش الف + نقش هر کدام: first frame / subject / style / environment]
Clips: [تعداد] × 10s (اگر omni-flash گزینه‌های ۱/۳/۶ داد، همین عدد را آزاد وارد کن) | Format: 9:16
Mood/style: [از قفل آرت]
On-screen text: NONE in every clip — all Persian text, badges and subtitles are added in edit
Brand lockup: NONE, except the final clip of the final episode (if the brief asks for a logo)
Audio direction: ambience + SFX + light music only — NO narration voice (VO recorded separately and added in edit)

Storyboard:
Clip 1 — [0-3s] … · [3-7s] … · [7-10s] …
Clip 2 — …
Continuity: same character design, outfit and palette as reference sheets in every clip
```
در `hybrid` فقط کلیپ‌های انیمیشنی (بدنه) در این بلوک می‌آیند؛ کلیپ‌های راوی جلوی دوربین به کیت فیلم‌برداری (ج) می‌روند.
این بلوک همراه تصاویر مرجع به omni-flash-motion-prompt داده می‌شود؛ آن اسکیل پاسخ‌های مرحله ۱ و استوریبورد مرحله ۳ خودش را از این بلوک برمی‌دارد و از تأیید استوریبورد ادامه می‌دهد.
دلیل دو خط NONE: قالب پیش‌فرض آن اسکیل در بیت `[7-10s]` هر کلیپ لوگو می‌گذارد، و مدل‌های ویدیو متن فارسی را قابل‌اعتماد رندر نمی‌کنند.

### ج) کیت فیلم‌برداری (فقط on_camera / hybrid)
```
SHOOT KIT — Episode [n]
A-roll (راوی جلوی دوربین): کلیپ‌ها · قاب (MCU/CU) · جهت نگاه · حس
B-roll لازم: [فهرست نماهای واقعی شاهد دیدنی، هر کدام با کلیپ مقصد و ثانیه]
تله‌پرامپتر: [متن راوی با / برای مکث]
صدا: میکروفون یقه‌ای، محیط کارخانه/مکان جدا ضبط شود (برای لایه‌ی SFX)
```

### د) یادداشت تدوین (همه‌ی حالت‌ها)
- VO روی کلیپ‌ها با هم‌زمانی کلمه‌ی کلیدی ← تصویر
- زیرنویس فارسی سوزانده‌شده، جدا از متن روی صفحه‌ی طراحی‌شده
- نشان «X/N» ثابت در گوشه در کل قسمت

## ۸.۳ — برنامه‌ی انتشار

**تک‌قسمتی:** فقط زمان انتشار پیشنهادی + کامنت اول + پین در صورت نیاز؛ بندهای لینک سریال و فاصله‌ی قسمت‌ها حذف. در کتاب سریال، «جدول فصل» یک ردیف دارد و لاگ‌لاین درباره‌ی همین یک قسمت است.


- **فاصله‌ی قسمت‌ها:** ۱ تا ۳ روز؛ هرگز بیش از یک هفته.
- **لینک سریال در اینستاگرام:** هنگام انتشار قسمت ۲ و ۳، قسمت‌ها را با قابلیت series/لینک ریلز به هم وصل کن (دکمه‌ی «قسمت بعد»). اگر این قابلیت در حساب فعال نیست: کامنت اول پین‌شده با لینک قسمت قبل.
- **پین:** قسمت ۱ روی پروفایل پین شود تا بیننده‌ی تازه از ابتدا وارد شود.
- **کپشن هر قسمت:** اشاره به قسمت قبل/بعد.
- **سنجش:** متریک مرحله ۰ + «٪ بیننده‌ی قسمت ۱ که قسمت ۲ را دید». اگر قسمت‌ها منتشر شدند و جواب ندادند → اسکیل hook در مود diagnose.

## ۸.۴ — چک‌لیست پیش‌تحویل

```
[ ] بریف اجرایی ۴ جواب دارد
[ ] لاگ لوپ: امتیاز نهایی > ۹ با شاهد + همه‌ی دروازه‌ها پاس
[ ] سربرگ پارامتر در خط دوم
[ ] هر قسمت: جدول کلیپ کامل (با برچسب) + VO کامل + کپشن + کاور + هشتگ
[ ] هر کلیپ ۱۰s و سه بیت
[ ] بلوک تحویل متناسب با PRESENCE کامل است (animation: الف + ب + د · on_camera: ج + د · hybrid: الف + ب + ج + د)
[ ] برنامه‌ی انتشار
[ ] همه‌ی [تأیید کارفرما]ها در بخش ۹ فهرست شده‌اند
[ ] هیچ نام مرحله/لایه در متن قسمت‌ها نیست
```
هر بند فِیل = برگرد و کاملش کن، بعد تحویل بده.
