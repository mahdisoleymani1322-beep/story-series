# مرحله ۷ — لوپ کیفیت (truth + امتیاز تا بالای ۹)

> هدف: پیش‌نویس کامل فصل را آن‌قدر نقد و بازنویسی کنی که امتیاز **بالای ۹ از ۱۰** بگیرد — با شاهد، نه با تعارف.
> لوپ **سقف دور ندارد**. ولی قانون‌های ضدتورم و گیرکردن پایین اجباری‌اند.

---

## ۷.۱ — چرخه‌ی هر دور

```
۱. پیش‌نویس فعلی (نسخه‌ی n)
۲. نقد مستقل با truth روی نسخه‌ی n  (نقد n)      ← بخش ۷.۲
۳. امتیازدهی نسخه‌ی n با رابریک + شاهد          ← بخش ۷.۳
۴. ثبت در لاگ                                    ← بخش ۷.۶
۵. شرط خروج — همه باید برقرار باشند:
   - امتیاز > ۹٫۰ و همه‌ی دروازه‌های سخت پاس
   - n ≥ ۲ (حداقل یک بازنویسی بر اساس truth انجام شده)
   - نقد n هیچ ضعفی نگفته که یک دروازه‌ی سخت را فِیل کند
   برقرار → برو مرحله ۸.
   وگرنه: بزرگ‌ترین ضعف نقد n، سپس بقیه‌ی ضعف‌ها و زیرمعیارهای فِیل را اصلاح کن → نسخه‌ی n+1 → برگرد به ۲
```

---

## ۷.۲ — پروتکل truth

اسکیل **truth** را روی پیش‌نویس اجرا کن با این ورودی:
- کل پیش‌نویس فصل (جدول فصل + جدول کلیپ‌ها + VO)
- مخاطب، هدف و معیار موفقیت از مرحله ۰
- این نقش‌ها برای نقد: **بیننده‌ی شکاک از مخاطب هدف** · **متخصص حوزه** (دنبال غلط فنی) · **تدوینگر ریلز** (دنبال افت ریتم)

**به truth امتیاز خودارزیابی را نشان نده** — نقد باید مستقل بماند.

از خروجی truth این‌ها را بردار: جمع‌بندی یک‌خطی · **بزرگ‌ترین ضعف** · ۲ تا ۴ ضعف دیگر · «چه چیزی نظر را عوض می‌کند».
هر ضعف را به یک معیار رابریک نگاشت کن؛ ضعفی که به هیچ معیاری نمی‌خورد با برچسب «آزاد» ثبت می‌شود. نقد n ورودی بازنویسی نسخه‌ی n+1 است و G2/G3 نسخه‌ی n+1 با آن سنجیده می‌شوند.

## ۷.۳ — رابریک ۱۰ امتیازی

شناسه‌ی معیارها (A1، L2، …) با شماره‌ی کلیپ‌ها (C1، C2، …) فرق دارد؛ گروه درس عمداً L نام دارد.
هر زیرمعیار پاس/فیل. امتیاز = جمع وزن‌های پاس. **هر پاس یک شاهد دارد** (نقل مستقیم از پیش‌نویس یا عدد شمرده‌شده). پاسِ بی‌شاهد = فیل.

## ۷.۳.۱ — شمارش ماشینی (قبل از امتیازدهی هر دور)

اگر اجرای کد در دسترس است، پیش‌نویس را در قالب مرحله ۸ در یک فایل بنویس و اجرا کن:
```
python3 <پوشه‌ی این اسکیل>/scripts/verify.py draft.md
```
- هر `FAIL` اسکریپت، زیرمعیار متناظرش را **فیل** می‌کند، هر چه خودارزیابی گفته باشد (کلمات ← D1 · تعداد کلیپ و سه بیت ← F1 · برچسب‌ها ← L4 · یادآوری ← E1/D1 · سربرگ و بلوک‌ها ← F2 · لوپ ← P1 · ریتم جمله ← P2 · شکست الگو و تنوع ← P3).
- خلاصه‌ی خروجی اسکریپت (`TOTAL x/y`) در ستون «اصلاح انجام‌شده» دور بعد یا زیر لاگ ثبت می‌شود.
- اگر اجرای کد در دسترس نیست: ستون «کلمات» را با شمارش دستی کلمه‌به‌کلمه پر کن (زمان‌ها و نام گوینده شمرده نمی‌شوند) و در لاگ بنویس «شمارش دستی».

## ۷.۴ — قوانین ضدتورم امتیاز

خودارزیابی به‌طور طبیعی امتیاز را بالا نشان می‌دهد. پس:
1. **امتیاز بدون تغییر بالا نمی‌رود.** هر افزایش امتیاز باید به یک تغییر مشخص در لاگ نگاشت شود.
2. **معیار S با عدد**، نه تیک. «✓» خالی = فیل.
3. **بزرگ‌ترین ضعف truth همیشه اول** اصلاح می‌شود، حتی اگر به معیار کم‌وزن بخورد.
4. **truth در هر دور روی نسخه‌ی جدید دوباره اجرا می‌شود** — نقد دور قبل برای دور بعد کافی نیست.
5. اگر truth در دور جدید ضعفی گفت که دور قبل «رفع‌شده» ثبت شده بود، آن معیار دوباره فیل می‌شود.
6. **حداقل دو دور.** دور ۱ به‌خاطر G2/G3 حداکثر ۹٫۴ می‌گیرد و حتی اگر > ۹ شد، شرط خروج n ≥ ۲ اجازه‌ی تحویل نمی‌دهد.

## ۷.۵ — قانون گیرکردن (به‌جای سقف دور)

```
IF دو دور پشت سر هم افزایش امتیاز ≤ ۰٫۲
   → صیقل دادن متوقف؛ بازگشت ساختاری:
     مشکل در B یا L  → مرحله ۲ یا ۳ (قالب داستان / چینش LU)
     مشکل در A        → مرحله ۶ (عنوان سریال / زاویه‌ی تنش)
     مشکل در D        → مرحله ۵ (عوض کردن لحن)
     مشکل در P        → مرحله ۴ (لوپ، شکست) یا ۵ (ریتم جمله)
     مشکل در E        → مرحله ۳ (نوع پایان‌ها) و سپس ۶
     مشکل در F        → مرحله ۴ (شبکه‌ی کلیپ)
     مشکل در G1       → بازگشت لازم نیست: ادعا را حذف کن یا برچسب [تأیید کارفرما] بزن
 IF سه بازگشت ساختاری انجام شد و هنوز ≤ ۹
   → لوپ ادامه دارد، ولی به کاربر دقیقاً بگو کدام معیار مقاومت می‌کند و چه ورودی‌ای (معمولاً اطلاعات فنی واقعی) آن را حل می‌کند
```
فقط فایل مرحله‌ای که به آن برمی‌گردی دوباره باز می‌شود.
