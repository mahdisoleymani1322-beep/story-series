# مرحله ۰ — بریف اجرایی

> هدف این مرحله: تبدیل درخواست کاربر به **زبان اجرایی** قبل از هر کار خلاقانه.
> خروجی: بخش بالای کارت وضعیت. بعد از این مرحله این فایل دوباره باز نمی‌شود.

---

## ۰.۱ — استخراج پارامترها

از پیام کاربر استنباط کن. فقط اگر استنباط **ممکن نبود** بپرس.

| پارامتر | گزینه‌ها | پیش‌فرض |
|---|---|---|
| `TOPIC` | موضوع خام | — (اجباری) |
| `NICHE` | صنعت / خدمات / آموزش / سلامت / تکنولوژی / … | از موضوع |
| `AUDIENCE` | نقش مشخص، نه «همه» (خریدار صنعتی، پیمانکار، دانشجو، …) | از نیچ؛ اگر مبهم بپرس |
| `GOAL` | `trust` (اعتمادسازی برند) · `educate` · `follow` · `lead` (دایرکت/تماس) · `save` | `trust` وقتی BRAND هست (شرکتی یا برند شخصی)، `educate` وقتی BRAND نیست |
| `PRESENCE` | `animation` · `on_camera` (خود کاربر راوی جلوی دوربین) · `hybrid` | از عبارت کاربر: «انیمیشنی» / «خودم جلو دوربین» |
| `EPISODES` | ۱ تا ۵ (۱ = تک‌قسمتی) | اگر کاربر «یک ویدیو / یه دونه» گفت ← ۱ (قطعی). اگر عدد نگفت ← ۳، با امکان پیشنهاد تغییر در مرحله ۱ |
| `EP_LENGTH` | ۴۰ تا ۹۰ ثانیه، مضرب ۱۰ | ۶۰s (= ۶ کلیپ ۱۰ ثانیه‌ای) |
| `NARRATOR_TONE` | `naqqal` (نقال مدرن) · `documentary` · `friend` (رفیق صمیمی) | `friend` برای B2C، `documentary` برای B2B |
| `BRAND` | نام برند/کارفرما، اگر هست | — |
| `FACT_SOURCE` | برگه‌ی اطلاعات کارفرما / سایت / کاتالوگ / هیچ | هیچ ← همه‌ی ادعاهای فنی `[تأیید کارفرما]` |

**اگر کاربر طولی گفت** همان قطعی است؛ اگر مضرب ۱۰ نبود به نزدیک‌ترین مضرب ۱۰ گرد کن و در «فرض‌ها» ثبت کن (۴۵s ← ۵۰s). فقط اگر خارج بازه‌ی ۴۰–۹۰ بود بپرس.

---

## ۰.۲ — چهار سؤال بنیادین

این چهار جواب را **صریح** بنویس. این‌ها همان چیزی‌اند که لوپ کیفیت (مرحله ۷) با آن‌ها قضاوت می‌کند.

### ۱) هدف چیست؟
یک جمله با این قالب:
> بعد از دیدن هر N قسمت، **[مخاطب مشخص]** می‌داند که **[قاعده‌ی رفتاری قابل اجرا]** و نسبت به **[برند/منبع]** احساس **[اعتماد/کنجکاوی/…]** دارد.

قاعده‌ی رفتاری یعنی چیزی که مخاطب **انجام** می‌دهد، نه فقط «می‌داند».
- ❌ «مخاطب با QC آشنا شود»
- ✅ «خریدار کابل قبل از خرید، برگه‌ی تست جرقه و مقاومت هادی را از فروشنده می‌خواهد»

### ۲) موفقیت چگونه سنجیده می‌شود؟
دو سطح:
- **سطح محتوا (داخل لوپ):** امتیاز رابریک مرحله ۷ بالای ۹ با همه‌ی دروازه‌ها پاس.
- **سطح انتشار (بعد از انتشار):** یک متریک تصمیم‌گیر متناسب با GOAL:

| GOAL | متریک اصلی | متریک سریال |
|---|---|---|
| trust | نرخ سیو | ٪ بیننده‌ی قسمت ۱ که قسمت ۲ را هم دید |
| educate | نرخ سیو + شیر | همان |
| follow | فالو از غیرفالوور | فالو بعد از قسمت ۱ |
| lead | دایرکت/کامنت کلیدواژه | دایرکت بعد از قسمت آخر |
| save | نرخ سیو | — |

### ۳) چه ریسک‌هایی قابل قبول است؟
پیش‌فرض را بنویس و فقط در صورت تفاوت با خواسته‌ی کاربر عوض کن:
- ✅ قابل قبول: ساده‌سازی فنی برای فهم عمومی (به شرط غلط نبودن) · شخصیت و موقعیت تخیلی · لحن طنز ملایم · تعلیق نرم در پایان قسمت
- ❌ غیرقابل قبول: ادعای فنی یا عدد ساختگی · تحقیر رقیب با نام · ترساندن بی‌پشتوانه · تعلیق سخت (قطع وسط جمله) بدون تضمین قسمت بعد · نمایش سند/لوگوی شخص ثالث

### ۴) سیستم تا کجا اجازه‌ی تصمیم‌گیری دارد؟
| تصمیم | بدون پرسیدن | با اعلام در خروجی | فقط با اجازه |
|---|---|---|---|
| انتخاب قالب داستان، شخصیت‌ها، صحنه‌ها | ✓ | | |
| انتخاب لحن راوی، شکل احساسی | ✓ | | |
| تغییر تعداد قسمت‌ها | | ✓ (پیشنهاد + دلیل) | اگر کاربر عدد مشخص گفته |
| حذف یک LU به‌خاطر ظرفیت | | ✓ | |
| هر ادعای فنی بدون منبع | | ✓ با برچسب `[تأیید کارفرما]` | |
| طول خارج از بازه‌ی ۴۰–۹۰s | | | ✓ |
| تغییر هدف یا مخاطب | | | ✓ |

## ۰.۳ — سؤال‌های ضروری (فقط اگر لازم)

سؤال ۱ و ۲ فقط اگر استنباط‌پذیر نبودند. سؤال ۳ فقط اگر **هر دو** شرط برقرار است: جلسه تعاملی است (کاربر حاضر است) **و** موضوع ادعای مخصوص یک برند دارد. همه را **در یک پیام** بپرس و منتظر بمان:
1. مخاطب دقیقاً کیست؟
2. انیمیشنی، خودت جلوی دوربین، یا ترکیبی؟
3. برگه‌ی اطلاعات فنی/تست‌ها/اعداد واقعی داری؟ (اگر نه، با برچسب `[تأیید کارفرما]` جلو می‌روم)

اگر هیچ‌کدام لازم نیست، نپرس و ادامه بده.

اگر کاربر در دسترس نیست یا جواب نداد: بهترین فرض را بکن، در بخش «فرض‌ها»ی کارت ثبت کن و ادامه بده.
